MAP 01

Self-managed local stack — every service on 127.0.0.1

One command brings up everything: scripts/run_stack.sh preflights .env, then starts docker/docker-compose.yml (platform, Prometheus, Grafana, OpenSearch, pgvector) and docker/langfuse-compose.yml (self-hosted Langfuse + its Postgres/ClickHouse/Redis/MinIO). Kubernetes is a local kind cluster; kind + kubectl live in tools/bin so nothing global is installed.

MAP 02

LangGraph pipeline — investigation graph · as a real graph

Every LLM step is a LangGraph node in a single StateGraph with a shared GraphState, compiled to backend/graph.py:app (compiled = graph.compile()). First node decides the route: detect sends a report to investigate, which either no-ops (benign/known) or triggers rag_retrieve. Diagnostics pull live evidence — the tags told you what each scene was; here we run the probe itself. swarm_r routes to dispatch when the swarm runs; swarm_r2 goes to self-heal; on diagnosed the graph computes risk_score, formats evidence, and exits through the human-approval gate → finalize — the rail stages DETECT · INVESTIGATE · RAG · DIAGNOSE · RISK · ACTION · SEAL are these exact nodes.

MAP 03

Fused RAG — three retrieval engines over the same knowledge

The knowledge base is backend/knowledge/**/*.md — seeded once by backend/seed_rag.py into pgvector (1528-demo embeddings) and opensearch (Lexical), with the vector–lexical mix kept as a fused score. KnowledgeBase combines all three engines — vector() + lexical() + tfidf() — each with an entrypoint tag, and re-ranks. K8s radar graphs, falco/audit texts, runbooks and MITRE mappings all live here.

MAP 04

Policy engine & approval gate — fail-closed, human-in-the-loop

The policy engine (backend/policy/engine.py) is authoritative: whatever the LLM proposes, the policy decides — risk is binned (light/runbook/major), then every action needs an approval (backend/controllers/approval.py). Nothing executes until a human clicks approve; an AUTO action is a policy misfire and is re-submitted for human decision. MCP execute runs only through the gate — validate → allowlist → policy → authorize → run → audit → verify.

MAP 05

MCP servers & tools — the only way changes run

Everything a change does runs through MCP, never ad-hoc: backend/mcp/server.py auto-discovers validated tools and starts gateway/backend/self-heal servers.

MAP 06

Scenario registry — every incident the simulator can replay

One central table SCENARIOS in backend/simulation.py drives the whole simulation — each entry records the k8s alert, the offending pod, whether the detector should fire, the runbook tag (filters RAG retrieval) and the final action. The registry is the single source of truth for the demo scenes (crashloop, priv-scaling, misconfig, pod-sandbox, viral pods …).

MAP 07

Detection → investigation — from a yaml severity to a verdict

Rules ship as yaml (monitoring/prometheus/rules/*.yml alerts, Grafana alerting/); the detector converts them into K8s Events via backend/detector.py. Falco triggers land through backend/virtual_falco.py; audit events come from the k8s audit log simulation. An incident is raised once — severity from the rule, evidence enriched by the student-facing event model, persistence via backend/storage/.

MAP 08

Technology inventory — everything this repo runs on

FastAPI + Pydantic serve the platform; LangGraph orchestrates investigation; RAG is fused pgvector + opensearch + tfidf. Incident handling is traced in self-hosted Langfuse; changes only happen through the MCP layer behind the policy engine; everything is a container on 127.0.0.1 — no cloud.

MAP 09

Where the LLM is used — and where it is not

One facade, backend/services/llm.py, serves three providers — mock (deterministic, always works offline), openai (any OpenAI-compatible endpoint, also vLLM/llama.cpp) and ollama (local). The model is used only for reasoning: explain, summarise, propose. It never executes anything.

✍️ diagnose — LangGraph node LLM writes structured JSON diagnosis from evidence + RAG context (llm.py::diagnose) mock mode produces the same shape deterministically
🎲 assess_risk — risk oracle risk is computed by a deterministic bound (_risk_for) — the model never sets risk unchecked LLM input is advisory; the policy engine is authoritative
🛡 security scanner — advisory prose per-finding paragraph: what the issue is, why it matters, a proposed remedy (llm.py::diagnose_finding) ends with “POLICY ENGINE AUTHORITATIVE — LLM IS ADVISORY ONLY.”
🔭 everywhere else — traced, not trusted every LLM / graph / MCP call is traced to self-hosted Langfuse (tracer.py) highlight: assume-breach guard (llm.py::_assume_breach)

Never the model: no shell, no kubectl, no deployment changes, no secrets leakage. Execution happens only through MCP after the policy engine decides and a human approves — fail-closed on 127.0.0.1.
